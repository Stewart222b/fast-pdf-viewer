## 任务 1：中文文件名导致打开失败

状态：已实现并通过自动化回归，待 Windows 实机验收。优先级：高。

位置：`desktop/app.py`，`Handler._serve_opened()`，基线第 78–84 行。

现象与依据：响应头直接插入 `file_path.name`。Python HTTP 响应头使用 Latin-1 编码，`中文手册.pdf` 会触发 UnicodeEncodeError。影响通过 `/opened.pdf` 加载的文档，即命令行路径和桌面选文件流程；浏览器 file input 的内存加载不走该接口。

建议：使用 ASCII 兼容的 fallback 文件名和规范的 UTF-8 扩展文件名参数，或在确认不需要文件名响应头后移除该头。处理引号等特殊字符，不要直接拼入原始文件名。

验收：

- 中文、英文、空格和特殊字符文件名均能通过 HTTP 返回正确的 PDF 字节。
- 响应头编码不报错且格式有效。
- Windows 桌面选择中文文件、命令行打开中文文件均成功；如没有 Windows 环境，明确保留为待实机验证。

## 任务 2：文档切换污染状态与后台任务

状态：已实现并通过自动化回归，待 Windows 实机验收。优先级：高。

位置：`web/js/viewer.js` 的 `open()`、`close()`、`renderPage()`、`indexText()`；`web/js/main.js` 的打开、目录和搜索异步流程。

现象与依据：

- close 仅取消部分 canvas 渲染，未销毁 PDF 文档或保留并取消加载任务；页码、页数、文件名、索引引用和缩放计时器也没有完整清理。
- indexText 在 await 前后反复访问可变的 `this.pdf` 与 `this.pageCount`。模拟 A 文档索引等待期间切到 B，旧任务最终写出了 `['A', 'B']`。
- open、文本层渲染、目录和搜索也存在异步返回，需检查过期结果是否可能覆盖新文档。

建议：引入文档代次/任务标识；异步流程捕获所属文档，写入 UI 或缓存前确认仍有效。保存并按生命周期销毁 loading task / PDF，取消旧渲染、文本层和计时器，重置文档状态。按实际 pdf.js API 管理清理顺序，避免取消造成未处理 Promise rejection。

验收：

- 快速连续打开 A、B，最终标题、页数、目录、画面和搜索结果全部属于 B。
- A 的慢索引晚于 B 完成时，也不能覆盖 B 的索引。
- 从长文档第 50 页切换到短文档，从有效初始页开始，工具栏状态一致。
- 加载中切换、渲染中切换和旧文档加载失败，都不会污染当前文档或产生未处理异步错误。
- 旧文档资源按所用 pdf.js 版本的生命周期 API 释放；用可控延迟的回归测试验证竞争条件。

## 任务 3：搜索高亮清理和命中定位

状态：已实现并通过自动化回归；真实 pdf.js 文本层视觉位置待验收。优先级：高。

位置：`web/js/viewer.js` 的 `showHits()`、`jumpToHit()`、`paintHighlights()`、`indexText()`；`web/js/main.js` 的 `runSearch()`；`web/js/search.js`。

现象与依据：

- showHits 只遍历新 hits 对应页面。清空搜索时页面集合为空，旧高亮不会清理；从关键词 A 换成 B 时，只有 A 命中的页面也会留下高亮。空结果模拟确认清理次数为 0。
- jumpToHit 仅跳页首，未按命中矩形滚动。同页不同位置的结果不能逐个定位到可见区域。
- indexText 用空字符串连接所有文本块，忽略行结束和块间间隔。可能漏掉短语或跨块错误命中；具体 PDF 样例需要补充。
- runSearch 等待全文索引后继续执行，没有查询代次检查；需避免快速输入时旧查询回写。

建议：清理旧、新命中页的并集；定位当前命中的实际矩形并确保进入可视区，历史记录对应最终位置；通过查询标识忽略过期结果。文本归一化如加入空格/换行，必须同步建立搜索文本偏移到原文本项的映射，不能只修改 join 而破坏高亮定位。

验收：

- 搜索 A 后清空输入，所有旧高亮消失，计数及按钮恢复空状态。
- A 改为 B 或无结果关键词，旧命中页无残留高亮。
- 同页上、中、下有多个命中时，点击结果和上下条按钮均让当前命中可见，计数正确。
- 索引未完成时连续输入多组查询，最终结果只对应最后的输入；切换文档后不出现旧搜索结果。
- 普通英文、中文及跨文本块短语的匹配和高亮一致；为归一化行为提供明确样例。扫描件 OCR 不在本任务范围。
- 搜索跳转后返回原阅读位置正确。
